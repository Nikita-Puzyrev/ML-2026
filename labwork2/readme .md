# Прогнозирование временного ряда с помощью нейронной сети

## Подробный разбор двух реализаций: NumPy и TensorFlow/Keras

---

# 1. Цель материала

В этом конспекте рассматривается одна и та же задача в двух вариантах:

1. **Ручная реализация нейронной сети с помощью NumPy**  
   Здесь явно реализуются:
   - веса и смещения;
   - прямое распространение сигнала;
   - функция активации ReLU;
   - функция ошибки MSE;
   - обратное распространение ошибки;
   - градиентный спуск;
   - обучение по эпохам.

2. **Реализация той же задачи с использованием TensorFlow/Keras и scikit-learn**  
   Здесь большая часть математических операций скрыта внутри библиотечных классов.

Главная идея сравнения:

> Библиотечная нейронная сеть не делает ничего принципиально другого.  
> Она автоматизирует те же операции, которые можно реализовать вручную.

# 2. Постановка задачи

Используется временной ряд количества арендованных велосипедов.

Источник данных:

- **Seoul Bike Sharing Demand Dataset**
- UCI Machine Learning Repository
- https://archive.ics.uci.edu/dataset/560/seoul+bike+sharing+demand

Целевая переменная:

```text
Rented Bike Count
```

Каждое наблюдение соответствует одному часу.

Задача:

> по предыдущим 24 часам спрогнозировать количество арендованных велосипедов на следующий час.

Если временной ряд имеет вид:

```text
100, 120, 135, 140, 130, ...
```

то при размере окна 3 создаются обучающие примеры:

```text
[100, 120, 135] -> 140
[120, 135, 140] -> 130
[135, 140, 130] -> ...
```

В нашей работе используется окно:

```python
WINDOW_SIZE = 24
```

То есть:

```text
24 предыдущих часа -> значение следующего часа
```

---

# 3. Почему временной ряд нужно превращать в окна

Обычная полносвязная нейронная сеть не хранит состояние предыдущих вызовов.

Она получает один вектор:

```text
[x1, x2, x3, ..., x24]
```

и возвращает результат:

```text
y
```

Поэтому временной ряд необходимо вручную преобразовать в набор признаков и целевых значений.

Функция:

```python
def create_windows(data, window_size):
    X = []
    y = []

    for i in range(window_size, len(data)):
        X.append(data[i - window_size:i])
        y.append(data[i])

    return np.array(X), np.array(y)
```

Для каждого момента времени `i`:

```python
data[i - window_size:i]
```

является входом сети.

А:

```python
data[i]
```

является правильным ответом.

---

# 4. Структура нейронной сети

В примере используется простая полносвязная сеть:

```text
24 входа -> скрытый слой -> 1 выход
```

Например:

```text
24 -> 16 -> 1
```

Это означает:

- 24 входных значения;
- 16 нейронов скрытого слоя;
- 1 выходной нейрон.

Схематично:

```text
x1  ─┐
x2  ─┤
x3  ─┤
...  ├──> 16 нейронов ReLU ───> 1 выход
x23 ─┤
x24 ─┘
```

---

# 5. Что получает один нейрон

Каждый нейрон вычисляет:

\[
z = x_1w_1 + x_2w_2 + \dots + x_nw_n + b
\]

или в более компактной форме:

\[
z = XW + b
\]

где:

- \(X\) — входные значения;
- \(W\) — веса;
- \(b\) — смещение;
- \(z\) — результат линейной комбинации.

После этого обычно применяется функция активации.

---

# 6. Функция активации ReLU

В скрытом слое используется:

```python
def relu(x):
    return np.maximum(0, x)
```

Математически:

\[
ReLU(x) = \max(0, x)
\]

Примеры:

```text
ReLU(-5) = 0
ReLU(-1) = 0
ReLU(0)  = 0
ReLU(2)  = 2
ReLU(10) = 10
```

ReLU делает сеть нелинейной.

Без нелинейной функции активации несколько линейных слоёв математически можно было бы свести к одному линейному преобразованию.

---

# 7. Почему выходной слой не использует ReLU

Выходной слой имеет вид:

```python
prediction = A1 @ W2 + b2
```

Функция активации после него не используется.

Причина:

мы решаем **задачу регрессии**, то есть сеть должна возвращать произвольное вещественное число.

Если использовать, например, `sigmoid`, результат искусственно ограничится диапазоном:

```text
0 ... 1
```

Если использовать ReLU, сеть никогда не сможет выдать отрицательное значение.

Для данной задачи линейный выход наиболее удобен.

---

# 8. Нормализация данных

Исходные значения количества велосипедов могут отличаться в сотни и тысячи раз.

Перед обучением удобно привести значения к диапазону примерно от 0 до 1.

Формула Min-Max нормализации:

\[
x_{norm} =
\frac{x-x_{min}}
{x_{max}-x_{min}}
\]

Пример:

```text
xmin = 0
xmax = 2000
x = 1000
```

Тогда:

```text
xnorm = 0.5
```

---

# 9. Очень важное правило: scaler обучается только на train

Нельзя вычислять минимум и максимум по всему временному ряду.

Неправильно:

```python
scaler.fit(values)
```

Почему это ошибка?

Потому что будущая тестовая выборка начинает влиять на подготовку обучающих данных.

Это называется:

```text
data leakage
```

или утечка данных.

Правильно:

```python
scaler.fit(values[:train_end])
```

После этого к остальным данным применяется:

```python
scaler.transform(...)
```

---

# 10. Разделение временного ряда

Обычные табличные данные часто случайно перемешивают.

Для временных рядов это делать нельзя.

Используется последовательное разделение:

```text
|--------- TRAIN ---------|--- VAL ---|--- TEST ---|
прошлое                                      будущее
```

Например:

```python
TRAIN_PART = 0.70
VAL_PART = 0.15
```

Получаем:

```text
70% train
15% validation
15% test
```

---

# 11. Зачем нужна validation-выборка

Train используется для изменения весов.

Validation используется для выбора архитектуры и контроля переобучения.

Test используется только для итоговой оценки.

Нельзя выбирать лучшую сеть по тестовой выборке.

Например, если сравниваются:

```text
24 -> 4 -> 1
24 -> 8 -> 1
24 -> 16 -> 1
```

лучший вариант выбирается по:

```text
Validation RMSE
```

и только после этого измеряется его результат на test.

# 12. Ручная реализация нейронной сети

## 12.1. Создание весов

Рассмотрим:

```python
self.W1 = rng.normal(
    0,
    np.sqrt(2 / input_size),
    size=(input_size, hidden_size)
)

self.b1 = np.zeros((1, hidden_size))
```

Если:

```text
input_size = 24
hidden_size = 16
```

то:

```text
W1.shape = (24, 16)
b1.shape = (1, 16)
```

Матрица `W1` содержит веса связей:

```text
24 входных признака
×
16 скрытых нейронов
```

---

# 13. Второй слой

```python
self.W2 = rng.normal(
    0,
    np.sqrt(2 / hidden_size),
    size=(hidden_size, 1)
)

self.b2 = np.zeros((1, 1))
```

При 16 скрытых нейронах:

```text
W2.shape = (16, 1)
```

То есть каждый из 16 скрытых нейронов связан с выходным нейроном.

---

# 14. Зачем веса задаются случайно

Если всем нейронам дать одинаковые начальные веса, они будут:

- получать одинаковые сигналы;
- вычислять одинаковые градиенты;
- одинаково изменяться.

То есть скрытые нейроны фактически будут дублировать друг друга.

Случайная инициализация нарушает эту симметрию.

---

# 15. Прямое распространение

Основная часть:

```python
def forward(self, X):

    self.Z1 = X @ self.W1 + self.b1

    self.A1 = self.relu(self.Z1)

    self.Y_pred = self.A1 @ self.W2 + self.b2

    return self.Y_pred
```

Разберём каждую строку.

---

# 16. Первый слой

```python
self.Z1 = X @ self.W1 + self.b1
```

Если:

```text
X.shape = (128, 24)
W1.shape = (24, 16)
```

то:

```text
Z1.shape = (128, 16)
```

Здесь `128` — размер batch.

Для каждого из 128 объектов вычисляются значения 16 скрытых нейронов.

---

# 17. Функция активации

```python
self.A1 = self.relu(self.Z1)
```

После ReLU размерность не меняется:

```text
A1.shape = (128, 16)
```

Меняются только значения.

---

# 18. Выход сети

```python
self.Y_pred = self.A1 @ self.W2 + self.b2
```

Размерности:

```text
(128, 16) @ (16, 1)
```

Получаем:

```text
(128, 1)
```

То есть для каждого объекта получено одно прогнозируемое значение.

---

# 19. Функция ошибки MSE

Используется:

```python
def mse(y_true, y_pred):
    return np.mean((y_true - y_pred) ** 2)
```

Формула:

\[
MSE =
\frac{1}{N}
\sum_{i=1}^{N}
(y_i-\hat{y_i})^2
\]

Если прогноз совпадает с реальным значением:

```text
ошибка = 0
```

Чем сильнее прогноз отличается от ответа, тем больше ошибка.

---

# 20. Идея обучения

Нейронная сеть должна найти такие веса:

```text
W1
b1
W2
b2
```

при которых функция ошибки минимальна.

Схематично:

```text
вход
 ↓
нейронная сеть
 ↓
прогноз
 ↓
сравнение с правильным ответом
 ↓
ошибка
 ↓
изменение весов
 ↓
новый прогноз
```

Этот цикл повторяется много раз.

---

# 21. Обратное распространение ошибки

В ручном варианте реализуется метод:

```python
backward()
```

Он отвечает на вопрос:

> Как изменение каждого веса влияет на итоговую ошибку?

Для этого используются производные.

---

# 22. Производная MSE

Если:

\[
L =
\frac{1}{N}
\sum(\hat y-y)^2
\]

то:

\[
\frac{\partial L}
{\partial \hat y}
=
\frac{2(\hat y-y)}{N}
\]

В коде:

```python
dY = 2 * (self.Y_pred - y) / n
```

---

# 23. Градиенты выходного слоя

```python
dW2 = self.A1.T @ dY
```

Это производная ошибки по весам выходного слоя.

```python
db2 = np.sum(
    dY,
    axis=0,
    keepdims=True
)
```

Это производная по смещению.

---

# 24. Передача ошибки назад

Ошибка распространяется от выходного слоя к скрытому:

```python
dA1 = dY @ self.W2.T
```

Отсюда и название:

```text
backpropagation
```

— обратное распространение ошибки.

---

# 25. Производная ReLU

Для ReLU:

\[
ReLU(x)=
\begin{cases}
0,&x\le0\\
x,&x>0
\end{cases}
\]

Производная:

\[
ReLU'(x)=
\begin{cases}
0,&x\le0\\
1,&x>0
\end{cases}
\]

В коде:

```python
def relu_derivative(x):
    return (x > 0).astype(float)
```

---

# 26. Градиенты первого слоя

```python
dZ1 = dA1 * self.relu_derivative(self.Z1)
```

После этого:

```python
dW1 = X.T @ dZ1
```

и:

```python
db1 = np.sum(
    dZ1,
    axis=0,
    keepdims=True
)
```

Теперь известны градиенты для всех обучаемых параметров сети.

---

# 27. Градиентный спуск

Вес обновляется так:

\[
W_{new}
=
W_{old}
-
\eta
\frac{\partial L}{\partial W}
\]

где:

- \(\eta\) — learning rate;
- \(\frac{\partial L}{\partial W}\) — градиент.

В коде:

```python
self.W2 -= self.learning_rate * dW2
self.b2 -= self.learning_rate * db2

self.W1 -= self.learning_rate * dW1
self.b1 -= self.learning_rate * db1
```

---

# 28. Что означает learning rate

Например:

```python
learning_rate = 0.005
```

Если learning rate слишком маленький:

- обучение идёт очень медленно.

Если слишком большой:

- сеть может перескакивать минимум функции ошибки;
- ошибка может колебаться;
- обучение может стать нестабильным.

---

# 29. Epoch и Batch

## Epoch

Одна эпоха означает:

> сеть один раз обработала всю обучающую выборку.

Если:

```python
epochs = 300
```

то сеть увидит train-набор примерно 300 раз.

---

## Batch

Обучающие данные обрабатываются частями.

Например:

```python
batch_size = 128
```

Вместо обновления весов после всей выборки сеть обновляет их после каждых 128 примеров.

Это называется:

```text
mini-batch gradient descent
```

---

# 30. Почему перемешивание batch допустимо

Сам временной ряд при разделении train/test перемешивать нельзя.

Но после того как окна уже созданы:

```text
[x(t-24)...x(t-1)] -> x(t)
```

готовые обучающие примеры можно перемешивать внутри train.

Порядок test и validation при этом сохраняется.

---

# 31. Полный алгоритм ручного обучения

```text
1. Получить batch X и y
2. Выполнить forward
3. Получить прогноз
4. Вычислить ошибку
5. Выполнить backward
6. Рассчитать градиенты
7. Обновить веса
8. Перейти к следующему batch
9. После обработки всех batch закончить эпоху
10. Повторить
```

---

# 33. Что означает Input


# 34. Что делает Dense

```python

    activation="relu"

```

```python
Z = X @ W + b
```

```python

```

Поскольку функция активации не указана:

```text
activation = linear
```

То есть слой выполняет:

```python
prediction = A1 @ W2 + b2
```

# 36. Компиляция модели

```python
model.compile(
```

```python
loss="mse"
```

означает:

# 38. optimizer=Adam

```python
optimizer = Adam(
    learning_rate=0.001
)
```

Adam — более современный вариант градиентной оптимизации.

Он использует информацию о предыдущих градиентах и автоматически корректирует шаг изменения параметров.

В простом ручном варианте было:

```python
W -= learning_rate * gradient
```

Keras выполняет более сложное и устойчивое обновление.

# 39. model.fit

Обучение:

```python
history = model.fit(

```

Эта команда внутри выполняет примерно следующий процесс:

```text
for epoch:
    for batch:
        prediction = forward(batch)
        loss = calculate_loss(...)
        gradients = backpropagation(...)
        optimizer.update(weights)
```

То есть одна строка:

```python
model.fit(...)
```

заменяет значительную часть ручной реализации.

# 42. patience

```python

```

означает:

> если validation loss не улучшался 15 эпох подряд, остановить обучение.

Это позволяет не выбирать число эпох вручную слишком точно.

# 43. restore_best_weights

```python

```

> после завершения обучения вернуть веса той эпохи, на которой validation loss был минимален.

Это удобнее, чем использовать веса последней эпохи.

# 46. MAE

Средняя абсолютная ошибка:

\[
MAE =
\frac{1}{N}
\sum |y_i-\hat y_i|
\]

В коде:

```python
mean_absolute_error(
    real,
    predicted
)
```

Преимущество MAE:

значение легко интерпретировать.

Например:

```text
MAE = 75
```

можно интерпретировать как:

> прогноз в среднем ошибается примерно на 75 велосипедов.

---

# 47. RMSE

\[
RMSE =
\sqrt{
\frac{1}{N}
\sum
(y_i-\hat y_i)^2
}
\]

В коде:

```python
rmse = np.sqrt(
    mean_squared_error(
        real,
        predicted
    )
)
```

RMSE сильнее штрафует большие ошибки.

# 48. Зачем нужны две метрики

Две модели могут иметь похожий MAE, но различаться по RMSE.

Например:

```text
Модель A:
MAE = 50
RMSE = 70

Модель B:
MAE = 50
RMSE = 150
```

У второй модели, скорее всего, иногда возникают очень большие ошибки.

---

# 49. Наивный прогноз

Очень важная часть работы:

```python
naive_prediction = X_test[:, -1]
```

Идея:

\[
\hat y_t = y_{t-1}
\]

То есть:

> значение следующего часа считаем равным значению предыдущего часа.

---

# 50. Почему нейронную сеть нужно сравнивать с baseline

Для временных рядов соседние значения часто очень похожи.

Поэтому модель может показывать визуально хороший график, но при этом проигрывать простому правилу:

```text
следующее значение = предыдущее значение
```

Если:

```text
Neural Network RMSE = 200
Naive RMSE = 120
```

то сложно утверждать, что нейронная сеть решила задачу хорошо.

```python
HIDDEN_SIZES = [4, 8, 16]
```

Получаем три сети:

```text
24 -> 4 -> 1
24 -> 8 -> 1
24 -> 16 -> 1
```

# 52. Больше нейронов не всегда лучше

Увеличение количества нейронов:

- повышает способность сети моделировать сложные зависимости;
- увеличивает число параметров;
- повышает риск переобучения;
- увеличивает вычислительную стоимость.

Поэтому нельзя утверждать:

```text
16 нейронов всегда лучше 8
```

Это проверяется экспериментально.

# 53. Как выбрать лучшую модель

Используется:

```python
best_row = results_df.loc[
    results_df["Validation RMSE"].idxmin()
]
```

То есть выбирается минимальный:

```text
Validation RMSE
```

а не Test RMSE.

---

# 54. Почему нельзя выбирать по Test RMSE

Если много раз смотреть на test и менять модель, исходя из результата, то test фактически превращается в validation.

После этого нельзя считать итоговую оценку независимой.

Корректная схема:

```text
TRAIN
  ↓
обучение

VALIDATION
  ↓
выбор архитектуры

TEST
  ↓
одна итоговая оценка
```

# 55. График ошибки

После обучения строится:

```python
plt.plot(
    history.history["loss"],
    label="Train"
)

plt.plot(
    history.history["val_loss"],
    label="Validation"
)
```

Возможны несколько ситуаций.

---

## Ситуация 1. Нормальное обучение

```text
Train loss       ↓
Validation loss  ↓
```

Это хороший признак.

---

## Ситуация 2. Переобучение

```text
Train loss       ↓↓↓
Validation loss  ↓ затем ↑
```

Сеть хорошо запоминает train, но хуже работает на новых данных.

---

## Ситуация 3. Модель не обучается

```text
Train loss       почти не меняется
Validation loss  почти не меняется
```

Возможные причины:

- learning rate слишком маленький;
- плохая нормализация;
- ошибка в данных;
- архитектура слишком слабая.

---

## Ситуация 4. Нестабильное обучение

```text
loss резко прыгает
```

Возможные причины:

- слишком большой learning rate;
- отсутствие нормализации;
- неудачная инициализация.

# 56. График прогнозов

На итоговом графике отображаются:

```text
фактический ряд
и
прогноз сети
```

Хороший прогноз должен:

- повторять основную динамику;

Однако визуальной оценки недостаточно.

Необходимо анализировать:

# 58. Сопоставление ручной реализации и Keras

| Ручная реализация | TensorFlow/Keras |
|---|---|
| `X @ W + b` | `Dense()` |
| `np.maximum(0, x)` | `activation="relu"` |
| собственная MSE | `loss="mse"` |
| ручной backpropagation | автоматический backpropagation |
| `W -= lr * grad` | `Adam()` |
| цикл `for epoch` | `model.fit()` |
| собственный forward | `model.predict()` |
| ручная остановка | `EarlyStopping()` |

# 63. Важный момент: циклические признаки

Час суток нельзя всегда удобно представлять просто числом:

```text
0, 1, 2, ..., 23
```

Потому что математически:

```text
23 и 0
```

оказываются далеко друг от друга, хотя во времени это соседние часы.

Можно использовать:

\[
sin(2\pi hour/24)
\]

и:

\[
cos(2\pi hour/24)
\]

В Python:

```python
df["hour_sin"] = np.sin(
    2 * np.pi * df["Hour"] / 24
)

df["hour_cos"] = np.cos(
    2 * np.pi * df["Hour"] / 24
)
```

# 64. Почему обычная Dense-сеть вообще может работать с временным рядом

Она не понимает время напрямую.

Но окно:

```text
[t-24, t-23, ..., t-1]
```

превращает временную структуру в обычный вектор признаков.

Сеть может научиться определять:

- тенденции;
- повторяющиеся шаблоны;
- локальные колебания.

---

# 65. Ограничение Dense-сети

Она рассматривает каждый элемент окна как отдельный признак.

Она не имеет внутренней памяти.

Если необходимо работать с длинными зависимостями, можно использовать:

- RNN;
- LSTM;
- GRU;
- 1D CNN;
- Transformer.

---

# 66. Переход к LSTM

Для LSTM форма данных должна быть другой.

Dense ожидает:

```text
(samples, features)
```

Например:

```text
(6000, 24)
```

LSTM ожидает:

```text
(samples, timesteps, features)
```

Например:

```text
(6000, 24, 1)
```

---

# 67. Пример LSTM

После этой лабораторной сеть можно заменить на:

```python
from tensorflow.keras.layers import LSTM

model = Sequential([
    Input(shape=(24, 1)),
    LSTM(32),
    Dense(1)
])
```

Это уже рекуррентная модель.

# 70. Вопросы для обсуждения на защите

### Вопрос 1

Почему нельзя просто передать нейронной сети столбец временного ряда?

**Ответ:**  
Обычная Dense-сеть ожидает фиксированный вектор признаков. Поэтому ряд преобразуется в окна предыдущих значений.

---

### Вопрос 2

Почему используется окно 24?

**Ответ:**  
Поскольку данные почасовые, окно 24 соответствует одним суткам и позволяет сети учитывать суточную динамику.

---

### Вопрос 3

Что произойдёт, если окно сделать равным 1?

Сеть будет видеть только:

```text
y(t-1)
```

и практически превратится в нелинейный вариант очень простого одношагового прогноза.

---

### Вопрос 4

Что произойдёт, если окно сделать равным 168?

```text
168 часов = 7 суток
```

Сеть сможет учитывать недельную историю, но:

- увеличится число параметров;
- обучение станет сложнее;
- возрастёт риск переобучения.

---

### Вопрос 5

Почему последний слой содержит один нейрон?

Потому что прогнозируется одно числовое значение.

---

### Вопрос 6

Почему используется ReLU?

Она:

- проста;
- быстро вычисляется;
- помогает моделировать нелинейные зависимости;
- хорошо работает во многих Dense-сетях.

---

### Вопрос 7

Что означает loss?

Это функция, которую оптимизатор пытается минимизировать во время обучения.

---

### Вопрос 8

Чем loss отличается от metric?

`loss` непосредственно используется для обучения.

`metric` обычно используется для удобной оценки результата.

---

### Вопрос 9

Почему используется Adam?

Он обычно обучает сеть стабильнее простого градиентного спуска и требует меньше ручной настройки.

---

### Вопрос 10

Почему сеть может проиграть наивному прогнозу?

Потому что временной ряд может быть очень инерционным, а:

\[
y_t \approx y_{t-1}
\]

может оказаться очень сильным baseline.

---

# 71. Короткий вывод

Ручная реализация показывает внутреннее устройство нейронной сети:

```text
вход
 ↓
умножение на веса
 ↓
bias
 ↓
ReLU
 ↓
выход
 ↓
MSE
 ↓
backpropagation
 ↓
обновление весов
```

Keras позволяет записать ту же идею значительно компактнее:

```python
model = Sequential([
    Input(shape=(24,)),
    Dense(16, activation="relu"),
    Dense(1)
])

model.compile(
    optimizer="adam",
    loss="mse"
)

model.fit(
    X_train,
    y_train
)
```

Главное, что студент должен вынести:

> `Dense`, `model.fit()` и `Adam` не являются магией.  
> Они автоматизируют матричные операции, вычисление производных и обновление весов, которые можно реализовать вручную.

После этой лабораторной логичным следующим шагом является переход к:

```text
RNN
LSTM
GRU
```

и сравнению рекуррентных сетей с обычной полносвязной сетью на той же задаче прогнозирования временного ряда.
